# 绿色通道中等规模实验对比总结

本文汇总 2026-05-22 至 2026-05-25 期间围绕 GAT-MARL Proactive 轻量入口节点绿色通道所做的中等规模验证实验。所有实验均使用 `data/processed/taxi_cleaned_active100_min100_eps2h_cov50.csv`，数据规模为 Top-12 active taxis，训练集 37832 rows / 9 taxis，测试集 11548 rows / 3 taxis，GAT-MARL epochs 均为 Proactive=8、Reactive=8。

本轮对比重点是 GAT-MARL Proactive，因为绿色通道参数只直接影响 Proactive 下的轻量入口节点 SLA rescue 行为。SA、Nearest、DQN 仍作为报告中的背景基线，但不作为本参数消融的主分析对象。

## 1. 实验参数设置

绿色通道逻辑主要由两个参数控制：

- `LIGHTWEIGHT_ENTRY_SCORE_FLOOR`：允许轻量入口节点在 counterfactual score 为轻微负数时仍被放行的下限。
- `LIGHTWEIGHT_ENTRY_MIN_SLA_GAIN_MS`：轻量入口节点进入绿色通道所需的最小 SLA 收益。

| 实验目录 | 简称 | Score Floor | Min SLA Gain | 参数含义 |
|---|---:|---:|---:|---|
| `medium_validation_20260522_1450_sla_severity_metrics` | 无绿色通道基准 | N/A | N/A | 只有 SLA severity 指标与 size guard，没有轻量入口亏损容忍 |
| `medium_validation_20260522_1711_light_entry_rescue` | 宽松绿色通道 | -1.0 | 0 ms | 只要轻量入口节点有正 SLA gain 且 score > -1.0 即可放行 |
| `medium_validation_20260524_1550_green_channel_tight` | 收紧版 | -0.5 | 1000 ms | 更严格地限制亏损动作，并要求显著 SLA 收益 |
| `medium_validation_20260524_1902_green_channel_mid` | 折中版 | -0.7 | 500 ms | 试图在 SLA 修复和迁移成本之间折中 |
| `medium_validation_20260524_2143_green_floor07_gain0` | 单变量：取消 gain 门槛 | -0.7 | 0 ms | 保持 score floor 不变，只测试 min gain 门槛影响 |
| `medium_validation_20260524_2148_green_floor10_gain500` | 单变量：放宽 score floor | -1.0 | 500 ms | 保持 500ms gain 门槛，只测试 score floor 放宽影响 |

## 3. 成本分解对比

总系统成本主要由 SLA penalty 与 migration cost 决定。其他项包括 tearing、communication、future、access latency，但量级远小于前两项。

## 4. 行为诊断指标对比

| 实验简称 | Entry Node Migrations | Avg Migrated Agents / Decision | Stay Action Ratio | Proactive Logit Bias Count | SLA Improving Action Count | Cost Guard Blocked Count |
|---|---:|---:|---:|---:|---:|---:|
| 无绿色通道基准 | 267 | 0.093 | 0.984 | 629 | 6173 | 17808 |
| 宽松绿色通道 | 353 | 0.170 | 0.969 | 706 | 3121 | 12477 |
| 收紧版 | 302 | 0.111 | 0.981 | 544 | 6101 | 17660 |
| 折中版 | 244 | 0.085 | 0.985 | 515 | 5974 | 17770 |
| 单变量：取消 gain 门槛 | 6279 | 2.208 | 0.623 | 1050 | 6159 | 8624 |
| 单变量：放宽 score floor | 219 | 0.078 | 0.987 | 600 | 6138 | 17894 |

诊断结论：

- `min_sla_gain=0ms` 会导致绿色通道失去关键安全阀。虽然 `score_floor=-0.7` 看起来比 `-1.0` 更保守，但取消最小 SLA 收益门槛后，入口节点迁移从百级跃升到 6279 次，`stay_action_ratio` 从 0.98 附近跌到 0.623，说明策略变成了高频迁移。
- `score_floor=-1.0, min_sla_gain=500ms` 没有触发迁移爆炸，说明 `min_sla_gain` 比 `score_floor` 更像主安全阀。
- `cost_guard_blocked_count` 在正常实验中维持在 1.7 万左右，而取消 gain 门槛时下降到 8624，说明大量本应被 cost guard 拦住的动作被绿色通道放行。

## 5. 各实验影响分析

### 5.1 无绿色通道基准

该版本已经具备 size-aware cost guard 和 SLA severity 统计，但没有轻量入口节点的亏损容忍。结果显示：

- `Avg Total System Cost` 为 8508.18，成本较低。
- `SLA Risk Count` 为 4830，`Severe SLA Violations` 为 796，P95 超距为 7.25km。
- 说明策略偏保守，能够控制迁移成本，但对 tail SLA 修复不足。

### 5.2 宽松绿色通道：`score_floor=-1.0, min_sla_gain=0ms`

该版本首次打开轻量入口节点绿色通道。结果显示：

- `SLA Risk Count` 从 4830 降到 3431，下降约 29.0%。
- `Severe SLA Violations` 从 796 降到 656，下降约 17.6%。
- `P95 SLA Excess` 从 7.25km 降到 5.91km，tail SLA 明显改善。
- 但 `Migration Cost` 从 778.72ms 升到 1277.05ms，`Avg Total System Cost` 升到 10411.90ms。

结论：该版本证明绿色通道方向有效，但过于偏向 SLA 修复，成本代价偏高。

### 5.3 收紧版：`score_floor=-0.5, min_sla_gain=1000ms`

该版本同时收紧两个条件。结果显示：

- 迁移次数从宽松版 357 降到 315。
- 总成本从 10411.90 降到 8765.67。
- 但 `SLA Risk Count` 回升到 4312，`Severe SLA Violations` 回升到 699。

结论：收紧版能有效压低成本，但牺牲了部分 SLA 修复能力。

### 5.4 折中版：`score_floor=-0.7, min_sla_gain=500ms`

该版本原本期望成为折中方案，但结果并不理想：

- `Avg Total System Cost` 降到 8271.78，是正常实验中最低的一组。
- `Migration Cost` 降到 479.71ms，迁移非常克制。
- 但 `SLA Risk Count` 升到 4838，已经略差于无绿色通道基准。
- `P95 SLA Excess` 为 6.22km，虽然优于无绿色通道基准，但弱于宽松版和收紧版。

结论：该版本过度保守，成本表现好，但绿色通道的 SLA 修复价值被削弱，不适合作为最终方案。

### 5.5 单变量实验：`score_floor=-0.7, min_sla_gain=0ms`

该实验专门验证 `min_sla_gain` 的影响。结果显示：

- 迁移次数暴涨到 6309。
- `Avg Migrated Agents / Decision` 达到 2.208，说明一次决策中平均迁移多个节点。
- `Migration Cost` 达到 13938.96ms，`Avg Total System Cost` 达到 21977.62ms。
- SLA 指标并未改善，`SLA Risk Count` 反而达到 5117。

结论：`min_sla_gain` 不能设为 0。即使有 `score_floor=-0.7`，缺少最小 SLA 收益门槛仍会导致大量低价值迁移被放行。

### 5.6 单变量实验：`score_floor=-1.0, min_sla_gain=500ms`

该实验专门验证放宽 score floor、保留 500ms gain 门槛的效果。结果显示：

- 迁移次数为 224，低于收紧版和折中版。
- `SLA Risk Count` 为 4534，优于折中版 4838，但弱于收紧版 4312。
- `Avg Total System Cost` 为 8434.37，低于收紧版 8765.67，略高于折中版 8271.78。
- `Migration Cost` 为 645.02ms，处于可接受范围。

结论：该版本比折中版更均衡。它保留了 `min_sla_gain=500ms` 作为安全阀，同时通过 `score_floor=-1.0` 给高价值轻量入口节点更多容忍空间。

## 6. 参数影响总结

### 6.1 `LIGHTWEIGHT_ENTRY_MIN_SLA_GAIN_MS` 是主安全阀

从 `-0.7 / 500ms` 与 `-0.7 / 0ms` 的对比可以看出：

- `min_sla_gain` 从 500ms 降到 0ms 后，迁移次数从 244 暴涨到 6309。
- 总成本从 8271.78ms 暴涨到 21977.62ms。
- SLA 反而变差，说明低 gain 动作大量放行会破坏迁移质量。

因此，`min_sla_gain` 必须保留，且不应低于 500ms，除非再引入更强的迁移频率约束。

### 6.2 `LIGHTWEIGHT_ENTRY_SCORE_FLOOR` 控制亏损容忍边界

从 `-0.7 / 500ms` 与 `-1.0 / 500ms` 的对比可以看出：

- 放宽 score floor 后，`SLA Risk Count` 从 4838 降到 4534。
- `Severe SLA Violations` 从 740 降到 726。
- `Avg Total System Cost` 从 8271.78 上升到 8434.37，代价很小。

因此，在保留 500ms gain 门槛的前提下，`score_floor=-1.0` 比 `-0.7` 更合理。

### 6.3 单纯追求最低总成本会削弱算法价值

折中版 `-0.7 / 500ms` 总成本最低，但 SLA Risk 已经接近甚至略差于无绿色通道基准。这说明如果只看 `Avg Total System Cost`，可能会选择过度保守的策略；论文中应同时报告 SLA Risk、Severe Violations 和 P95 SLA Excess，以体现迁移策略是否真正改善服务质量。

## 7. 推荐结论

当前最推荐的候选配置是：

```python
LIGHTWEIGHT_ENTRY_SCORE_FLOOR = -1.0
LIGHTWEIGHT_ENTRY_MIN_SLA_GAIN_MS = 500.0
LIGHTWEIGHT_ENTRY_MIN_BIAS = 0.2
```

理由：

- 相比折中版，SLA 修复更好，且总成本只小幅上升。
- 相比宽松原版，迁移成本大幅下降，总系统成本明显降低。
- 相比收紧版，总成本略低，迁移更克制，SLA 指标虽略弱但更均衡。
- 通过 `min_sla_gain=500ms` 保留了必要安全阀，避免 `min_sla_gain=0ms` 导致的迁移爆炸。

## 8. 论文或报告中的表述建议

可以将绿色通道实验表述为一个参数消融：

> The lightweight-entry rescue mechanism improves tail SLA when the score floor is relaxed, but it requires a minimum SLA-gain threshold to prevent low-value migrations. The ablation shows that removing the minimum gain threshold causes migration explosion, while retaining a 500ms gain threshold and allowing a score floor of -1.0 provides the best balance between SLA repair and migration cost.

中文表述：

> 轻量入口节点绿色通道可以提升尾部 SLA 修复能力，但必须配合最小 SLA 收益门槛。消融实验表明，取消最小收益门槛会导致迁移爆炸；在保留 500ms 最小收益门槛的情况下，将 score floor 放宽到 -1.0 能在 SLA 修复和迁移成本之间取得更稳定的平衡。

## 9. 注意事项

- `Avg Decision Time` 在两组并行运行实验中可能受到 CPU 争用影响，不应作为这几组参数实验的核心结论依据。
- `Avg Access Latency` 始终约 2.09ms，说明用户实际接入延迟本身稳定，系统成本差异主要来自 SLA penalty 与 migration cost。
- 不同实验中的 SA、DQN 结果存在一定随机波动，因此本文重点比较同一算法 GAT-MARL Proactive 在不同绿色通道参数下的变化趋势。

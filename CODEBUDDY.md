# CODEBUDDY.md

This file provides guidance to CodeBuddy Code when working with code in this repository.

## Project Overview

Edge computing microservice DAG migration research system. Moving users (taxis) trigger migration of microservice DAGs between edge servers to minimize SLA violations and migration cost. The core innovation is a CTDE-GAT-MARL architecture (Centralized Training, Decentralized Execution with Graph Attention Networks).

## Running Experiments

**Current recommended entry point** (Reward v2.1 P3, reactive-only, 8 MARL epochs):
```bash
python -u run_reward_v21_p3_cov50.py
```
Quick 2-epoch variant:
```bash
set MEDIUM_VALIDATION_MARL_EPOCHS=2 && python -u run_reward_v21_p3_cov50.py

**Single-algorithm entry points** (use preprocessed data automatically):

**Full algorithm comparison** (Nearest / SA / DQN / GAT-MARL):

**Smoke verification scripts** (no formal test suite exists):

```

## Configuration

All parameters are controlled via **environment variables** (no config files). Key ones:

| Variable | Default | Purpose |
|----------|---------|---------|
| `REWARD_SCHEME` | `v1` | Reward version (v1/v2) |
| `REWARD_V2_USE_INTERNAL_PATH` | `1` | v2.1: include internal path delay in SLA |
| `REWARD_V2_OBJECTIVE_SCALE_MS` | `50000` | v2 reward scaling |
| `MARL_TRAIN_TOTAL_COST` | `1` | Direction A: align training with total_cost_ms |
| `MARL_P1` | `1` | P1: entry-first + max-one-migration constraint |
| `MARL_CF_SLA_GAIN_GATE` | `1` | B1.1: CF SLA improvement hard gate |
| `MARL_CF_GATE_MODE` | `score` | CF gate mode (score/threshold) |
| `MEDIUM_VALIDATION_MARL_EPOCHS` | `8` | MARL training epochs |
| `MEDIUM_VALIDATION_REACTIVE_ONLY` | `0` | Skip proactive triggers |
| `MEDIUM_VALIDATION_INFERENCE_ONLY` | `0` | Skip training, only inference |
| `MEDIUM_VALIDATION_ACTIVE_USERS` | `12` | Number of taxi users |

Environment variables are set in `run_reward_v21_p3_cov50.py` before importing `run_medium_validation_cov50`, so the entry point script is the canonical config location.

## Key Concepts

**Trigger types** (`core/context.py`):
- **Reactive**: Current location already violates SLA (distance > 15km or QoS > threshold). Urgent, 1.5× migration cost multiplier.
- **Proactive**: Predicted trajectory indicates future violation (TTV within dynamic window). Lower cost, requires trajectory prediction.

**MARL action space** (`algorithms/marl_gat.py`):
- 4 actions per node: `[STAY, CANDIDATE_1, CANDIDATE_2, CANDIDATE_3]`
- P1 entry-first: non-entry nodes can only STAY in early steps
- P1 max-one: at most 1 migration per decision step (entry priority)
- B1.1 CF gate: migration only allowed if counterfactual SLA improvement is positive

**CTDE-GAT-MARL architecture**:
- GraphEncoder: GAT-style message passing over DAG adjacency → 64-dim node embeddings
- SharedNodeActor: all nodes share parameters, outputs Q(N,4)
- CentralCritic: global information (graph embedding + trigger + joint action) → V(1)
- Node features: 17-dim (location, distance, DAG properties, external flag) + 9-dim trigger context + 2-dim mobility + 12-dim candidate info

**Reward decomposition** (`core/marl_reward.py`):
- Shared reward: DAG-level (all agents get same signal)
- Per-agent: shared + dense distance bonus − λ × local migration cost
- Direction A (default): training reward = −total_cost_ms / 10000

**External nodes**: USER/UNKNOWN/UNAVAILABLE nodes are kept in the graph for encoding but never participate in migration actions, migration cost, or deployable entry SLA checks.

## Data Pipeline

`core/data_loader.py` handles the full pipeline:
1. Load raw taxi CSV → sort/dedup/clean velocity spikes
2. Filter: active users (≥100 points), top-100 by activity
3. Assign episode IDs (2-hour intervals), server coverage filter (cov50)
4. Cache to `data/processed/taxi_cleaned_active100_min100_eps2h_cov50.csv`

If the processed file exists, `load_data(processed_csv=...)` loads it directly (seconds). Otherwise it runs the full pipeline from raw data. Processed CSVs are gitignored.

## Important Constraints

- Do **not** increase Proactive default λ back to 0.5/0.2 (causes exploration collapse)
- Do **not** restore millisecond-scale dense bonus (e.g. `proactive_bonus_per_km=1000.0`)
- Do **not** solve "all STAY" by just adding more epochs
- Do **not** solve Reactive "all migrate" by just increasing λ
- External nodes must never participate in migration actions, cost, or deployable entry SLA
- When `node_feat_dim=14` changes (currently 17), old checkpoints are incompatible and must be deleted
